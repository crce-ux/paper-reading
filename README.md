# paper-reading

[![Skill self-check](https://github.com/crce-ux/paper-reading/actions/workflows/structure.yml/badge.svg)](https://github.com/crce-ux/paper-reading/actions/workflows/structure.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

**单篇文献的日常精读——从「要不要读」到「读成能复用的笔记」。**

- **解决什么问题**：把一篇文献读成能直接搬进证据表的笔记；读多深，决定能写出什么形式的引用。
- **一条命令跑通**：`python scripts/check_note.py <笔记.md>`
- **适用人群**：需要长期精读、笔记要向下游综述供料的研究生。

P 段不占档：它是**跨项目的常驻活动**，为下游各段共同供料。价值在于**把工作量前移**——
等真要写综述时，**读过的文献**已过人工筛选与理解，对接证据表时是**搬运，不是重做**。

---

## 核心：证据标签五态

**笔记里每一条断言，都要标出它是哪一类**——把「原文说的」和「我推断的」当场分开。

| 标签 | 含义 | 必须带什么 |
|---|---|---|
| `[Paper]` | **论文明确报告或声称**的 | 定位（页 / 章 / 图 / 表 / 式） |
| `[External]` | 论文**以外**的来源支持的 | 引用或链接 |
| `[Analysis]` | **我从已识别证据推断**的 | 推理 + 相关出处 |
| `[Hypothesis]` | 可检验但**未验证**的 | 检验方式 + 可能证伪条件 |
| `[User]` | **用户提供**的判断 | 原话或链到的知识 |

> 🔴 **不标 = 默认是 `[Paper]`，而「不标即当 `[Paper]`」是最危险的默认。**
> 一句你推断的话混在论文原话里，三个月后你自己分不出来——
> 最后它会以「文献支持」的名义进综述。

### 两条轴，别混

| 轴 | 标什么 | 例 |
|---|---|---|
| **可信度轴** | 待检来源可不可靠 | 🟢 一手 / 🟡 二手 / 🔴 未核实 |
| **归属轴** | 待检断言**是谁说的** | `[Paper]` / `[Analysis]` / `[Hypothesis]` / `[User]` |

**🟢🟡 解决不了归属问题**：一条 🟡 可以既是你推断的、也是别人转述的，两者处置完全不同。

## 定位方式三态——引用形式由源可靠性决定

**读多深，决定你能写出什么形式的引用。** **「读多深决定引用形式」不是风格**，是**不许越界**：

| 态 | 条件 | 引用写成 | 禁止 |
|---|---|---|---|
| **page-grounded** | PDF 页码可靠 | `[Paper: PDF p.3, Fig.2]` | — |
| **structure-grounded** | 页码不可靠，章节 / 图表可靠 | `[Paper: Fig.2]` | **不写页码** |
| **source-limited** | 只有摘要 / 元数据 | `[Paper: Abstract]` | **不写页码，不推断未见的方法与结果** |

> 页码引用看起来最「精确」，所以在页码不可靠时写它**伤害最大**——
> 它让读者以为你核对过对应页。**宁可用粗一点的定位，不要用假精确的。**

## 选什么读

| 该读 | 不该读（或只扫读） |
|---|---|
| **竞争文献**（同一问题别人也在做） | 只与主题沾边 |
| **方法学模板**（可照着自己的设计） | 结论已被更新研究取代（除非写「研究演变」） |
| **立论接口**（支撑某个论点的关键证据） | **二次转述**——追到原始文献 |
| **领域现状**（权威综述，**只作背景**） | 只能拿到摘要（可读，必须标「仅摘要」） |

## 三级深度

| 级 | 读到哪 | 产出 |
|---|---|---|
| **扫读** | 标题 → 摘要 → 图表 → 结论 | 一句话 + 值不值得深读 |
| **泛读** | 扫读 + 方法 + 结果 | 要点笔记 |
| **精读** | **全文逐段** + 批判性思考 | 完整笔记 |

**深度 → 能支撑什么**（超出即越界）：仅标题 ❌ 几乎不能 → 仅摘要 → **只能是作者自述的结论** → 全文 → 精确范围与条件。

---

## 三条硬规则

1. **每个数字必须能指向原文的具体位置**——指不出就不能写成断言
2. **转述必须回读完整段落**——局限性段落开头讲的与后半段讲的常常不是一回事
3. **竞争文献要写「威胁评估」**——它做到了什么、没做到什么、**我们的差异在哪**

## 回填：15 列 = 11 对齐 + 4 管理

```
_文献表.json        ← 真源（日常只追加它）
_文献表.xlsx / .md  ← 生成物（**不要手改**）
```

前 11 列**与证据表前 11 列同名同序**——所以对接时只需补「对本课题的意义」+ 按叙事重组，**不是重做**。

> ⚠️ 「对本课题的意义」**必须人工**——它需要课题上下文，是**判断**不是搬运。
> 「对本课题的意义」代填了，P 段「工作量前移」的价值就整个消失。

## 脚本

```bash
python scripts/check_note.py <笔记.md>              # 笔记机检
python scripts/check_note.py <文献精读目录> --dir    # 目录模式（按命名约定找）
python scripts/build_daily_ref.py --data _文献表.json -o .
```

`check_note.py` 查三组硬规则 + 一组软提示：

| | 查什么 |
|---|---|
| **N1** | 必备信息（标识符 / 可得性声明 / 定位方式）——**按信息找，不按字段名找** |
| **N2** | 用过标注吗（五态 或 🟢🟡 来源等级） |
| **N3** | ⭐ **定位方式与引用形式一致**——标了「仅摘要」却引用 `Table 2` = **在编** |
| N4 | （软）没带标签的断言行——只报数 |

**脚本只做可自动化的部分。**「这条推断合不合理」「这篇值不值得读」——脚本答不了。
