# 文献表 · 列定义与回填

> **管什么**：笔记读完之后，怎么进表、表长什么样、怎么搬到 A2。
> **不管什么**：笔记本身怎么写（见 `note-schema.md`）。

---

## 一、真源与生成物

```
_文献表.json        ← **真源**。日常只追加它
_文献表.xlsx / .md  ← 生成物。**不要手改**——下次生成会覆盖
```

```bash
python scripts/build_daily_ref.py --data "_文献表.json" -o "."
```

> 🔴 **改数据改 JSON，不改 xlsx。** 手改生成物 = 下次跑脚本时白改。

## 二、15 列 = 11 对齐 + 4 管理

| # | 列 | 说明 |
|---|---|---|
| 1 | 文献·DOI | 题名 + DOI |
| 2 | 作者·年份 | 第一作者 + 年份 |
| 3 | 研究设计 | RCT / 队列 / 横断面 / 综述… |
| 4 | 人群 (P) | **填全样本量**——只写「精神分裂症患者」不算填 |
| 5 | 干预暴露 (I/E) | |
| 6 | 对照 (C) | 无对照写 `NA`，**不留空** |
| 7 | 主要结局 (O) | |
| 8 | 关键结果 | 效应量 + CI，**回全文核过** |
| 9 | 局限 | 作者自陈 + 你的判断 |
| 10 | 期刊 IF | `6.6 (2025 JCR)` |
| 11 | 期刊分区 | `中科院医学2区(2025) / JCR Q1` |
| — | — | 以上 11 列**与证据表前 11 列同名同序** |
| 12 | 主题标签 | 供 A2 按主题筛选 |
| 13 | 精读状态 | `⬜未读 / 🔄在读 / ✅已精读 / 📝笔记完成` |
| 14 | 笔记链接 | 指向 `精读笔记_*.md` |
| 15 | 入库日期 | YYYY-MM-DD |

> ⭐ **1–11 对齐是 P 段设计的全部意义**：
> 对接 A2 时只需补「对本课题的意义」+ 按叙事重组，**不是重做**。

## 三、质量线（**必须守，否则对接时仍返工**）

- [ ] **「关键结果」回全文核对**——摘要常不载样本量与效应量，
      **而精读的价值恰在于有全文**。停在摘要 = 白精读
- [ ] **「人群」填全样本量**
      > 返工总表里「被追问答不上样本量」的根因，就是摘要未载、又没调全文
- [ ] **IF 用官方 JCR 值并标年份**：`6.6 (2025 JCR)`
- [ ] **分区写「中科院（标版本）+ JCR」**
      > ⚠️ 中科院分区有基础版 / 升级版差异且逐年变动，**不写口径等于没写**
- [ ] **中文刊 / 预印本 / 新刊查不到 → 允许留空**，不硬填

---

## 四、对接 A2（P → 证据表）

```
文献表.xlsx（15 列）
   │ ① 按「主题标签」筛选出相关条目
   │ ② 补第 12 列「对本课题的意义」        ← ⚠️ 人工
   │ ③ 按叙事分区组织 → 模块X_evidence.json
   │ ④ build_evtab.py --data 模块X_evidence.json --module 模块X
   ▼
证据表_模块X.xlsx（12 列）
   └→ 逐篇讲解 / 综述 / PPT
```

### ⚠️ 第 ② 步必须人工

**「对本课题的意义」需要课题上下文**——它回答的是「这篇对我这个课题意味着什么」。
**不能由脚本推断，也不能由 AI 代填**：那是**判断**，不是搬运。

> 🔴 这一步代填了，P 段「工作量前移」的价值就整个消失——
> 因为搬过去的是一堆没有立场的条目，写综述时还要重判一遍。

### 按主题标签筛选，不全搬

一篇文献常同时服务多个课题。**标签是筛选闸门。**
